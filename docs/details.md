# 京都を駆け抜けろ — 忍者鉤縄タイムアタック

KYOTO PLATEAU HACK 2026 の作品。**PLATEAU の京都市 3D 都市モデルをそのまま舞台にして**、忍者が鉤縄で実在の京都を駆け抜け、京都タワーの頂点を越えるまでのタイムを競うブラウザゲーム。

- 対象：大学生。遊びながら、京都の碁盤目・鴨川・名所の位置関係と、PLATEAU にどんなデータが入っているかが分かる。
- コース：七条通 → 鴨川・七条大橋 → 京都駅 → 東寺五重塔 → 京都タワー（実距離のまま 約 3.6km）。

デモ動画（1分47秒・自動操縦によるプレイ）：[demo/kyoto-ninja-demo.mp4](../demo/kyoto-ninja-demo.mp4)

## 特徴

| | 内容 | 使っている PLATEAU データ |
| --- | --- | --- |
| 実在の街が舞台 | 建物の形・高さ・壁面の写真がそのまま出て、当たり判定と鉤縄の固定先にもなる。京都駅・京都タワー周辺は LOD3 | 建築物モデル（下京区 LOD3、東山区・南区 LOD2、テクスチャ付き） |
| 川と橋 | 鴨川に落ちると足が遅くなり、七条大橋の上だけ渡れる | 土地利用モデル（水面）、道路モデル（橋梁区間） |
| 古い建物は壊れる | 1980 年以前に建った建物は、勢いよく突っ込むと崩れる。狙った建物の築年が画面に出る | 建築物モデルの属性 `bldg:yearOfConstruction` |
| 地面の起伏 | 東山側の坂にも地面が追従する | 建物の足元の高さから推定（京都市に地形モデルは無い） |
| タイムアタック | カウントダウン、区間タイム、自己ベスト | — |
| チーム戦 | 同じ合言葉を入れた人が同じチームになり、チームランキングで競う | — |
| ゴールの俯瞰 | 塔の上から、通った軌跡と碁盤目の街を見渡す | — |

## 遊ぶ

**https://kyoto-ninja.kyoto-ninja.workers.dev** を PC の Chrome か Edge で開く（キーボード＋マウス）。

- 建物データはプレイ中に PLATEAU の配信サーバーから読み込む。実写テクスチャ付きのタイルは 1 枚 5〜11MB あり、**初回の読み込みは 1〜2 分かかることがある**（検証環境で約 110 秒。2 回目以降はブラウザのキャッシュが効いて約 13 秒）。発表前に一度コースを通しで走っておくとよい。
- 高性能な PC では URL の末尾に `?hq` を付けると建物の写真が 4096px になる（標準は 2048px）。

## タイムアタックとチーム

カウントダウンの GO から、京都タワーの頂点を越えるまでのタイムを競う。GO までは動けず、タイムも進まない。

- **自己ベストと区間タイム**はブラウザに保存され、通過地点ごとに「ベスト比 ±秒」が出る。
- **チーム**：スタート画面で名前と合言葉を入れると、同じ合言葉の人が同じチームになる（1チーム8人まで）。最初に入った人がチーム名を付けられる。合言葉が空欄ならソロ。
- **ランキング**：チームの成績は「チーム内でいちばん速い人のタイム」。ゴール画面にチーム内順位とチームランキング（上位20）が出る。
- 記録は Cloudflare の Durable Objects に保存される。合言葉そのものは保存しない（ハッシュだけ）。
- 同じ URL を開いた人どうしなら、離れた場所からでも同じチームに入れる。
- タイムは各ブラウザからの自己申告で、不正対策はしていない（試遊会向け）。

## デプロイ（Cloudflare Workers）

公開先は https://kyoto-ninja.kyoto-ninja.workers.dev 。ゲーム本体（`index.html` と `dist/game.js`）を静的アセットとして配り、`/api/*` だけを Worker（`worker/index.js`）が受ける。チームの記録は Durable Object（`TeamStore`）1 つにまとめて保存する。

```bash
npm install
npx wrangler login
npm run deploy
```

- 外に出すのは `index.html` と `dist/game.js` だけ（ソースや設定は 404）。
- API は 1 つのアクセス元につき 1 分 60 回まで（チーム参加は 12 回まで）。超えると 429。
- 建物データは各プレイヤーのブラウザが PLATEAU の配信サーバーから直接読む（初回は数百 MB）。Cloudflare 側の通信量は小さい。
- タイムは各ブラウザからの自己申告で、不正対策はしていない。公開ランキングとして使うなら対策が要る。
- 同じ API を Node.js だけで動かす版（`server.js`、記録は JSON ファイル）と `Dockerfile` も残してある。Cloudflare 以外に載せるときや、ネットワークを閉じた会場で動かすとき用（`npm run serve`）。

## 古い建物は壊れる

狙った建物の建築年が画面中央の円の下に出る。**1980年以前に建った建物**（1981年の新耐震基準より前）は「もろい」と表示され、壁に秒速16m（時速約58km）以上で突っ込むと崩れて通り抜けられる。走る速さ（秒速13m）では壊れないので、鉤縄で勢いをつける必要がある。

- 建築年は PLATEAU の建物属性 `bldg:yearOfConstruction` をそのまま使用。値が入っていない建物（データ上は 1 など。スタート周辺で全体の約2割）は「不明」として壊れない。
- 屋根に着地しても壊れない（壁への衝突のみ）。
- **建物用途**（PLATEAU の属性 `bldg:usage`）も築年と一緒に表示する。住宅・共同住宅・店舗等併用住宅などの「住まい」を崩すと、タイムに +5 秒の罰が付く。ゴール画面には、鉤縄を掛けてきた建物の用途の内訳（住まい・商業・宿泊など）が出る。用途が「不明」の建物（検証した範囲で約 4 分の 1）は表示も罰もなし。
- ゴールの京都タワー（1964年竣工）と東寺五重塔の周辺は、古くても壊れない。
- 調整値は `src/breakable.js` の `OLD_YEAR` と `src/main.js` の `BREAK_SPEED`。

## コース（実距離のまま・直線合計 約 3.6km）

七条通（スタート）→ 鴨川・七条大橋 東詰 → 西詰 → 河原町塩小路 → 京都駅 八条口 → 東寺 五重塔 → 京都タワー

企画時の「川 → 五重塔 → 京都タワー」の順は、五重塔を東寺のものとすれば実地理のまま成立する（鴨川から南西へ約 2km、そこから北東へ約 1.3km）。地点の緯度経度は `src/config.js`。

## 使っているデータ

| 用途 | データ | 備考 |
| --- | --- | --- |
| 建物の形・高さ・壁面と屋根の見た目（表示／衝突／鉤縄の固定先） | 国土交通省 PLATEAU 京都市 2025 年度 建築物モデル（テクスチャ付き）3D Tiles。下京区＝LOD3（京都駅・京都タワー周辺）、東山区・南区＝LOD2（南区に LOD3 は無い） | 配信 URL は PLATEAU データカタログ API（`api.plateau.reearth.io/datacatalog/graphql`）で取得。表示と当たり判定は同じメッシュ（BVH で高速化） |
| 川・河川敷・敷地の用途（地面の描画／水面の判定） | PLATEAU 京都市 2025 年度 土地利用モデル（MVT、ズーム 16） | `luse_class` が「水面」のポリゴンを川として扱う |
| 道路・橋（地面の描画／川を渡れる場所） | PLATEAU 京都市 2025 年度 道路モデル LOD1（MVT、ズーム 16） | 区間種別が「橋梁」の道路は金色で描き、水面の上でも渡れる |
| 建物の建築年（壊れる建物の判定） | 同じ建築物モデルの属性 `bldg:yearOfConstruction` | 3D Tiles のバッチテーブルから建物 1 棟ごとに取得 |
| 地面の高さ | PLATEAU の建物の足元の高さから推定（京都市に地形モデルは無い） | 50m マスごとに建物の足元高さを集めてなめらかにつなぐ（`src/terrain.js`）。東山側の坂にも追従する |

建物の壁面・屋根は PLATEAU の実写テクスチャ（航空写真由来なので、地上から間近で見るとぼやける。日陰の面は暗く写っている）。元のテクスチャは最大 8192px で、メモリ節約のため 2048px（`?hq` 指定時は 4096px）に縮小して表示している。テクスチャの無い建物は無地の灰色。

ゲーム側で足した演出：夕暮れの色味（写真を明るめに補正）、星と月、目的地の光の柱、忍者。

## 確認したこと

- PLATEAU の建物・道路・川が互いにずれなく重なること（座標変換の検証。初期版では地理院タイルとも照合した）。
- 七条大橋が道路モデルの橋梁区間として入っていて、川の水面判定が橋の上だけ切れること。
- 京都タワーと京都駅ビルが実写テクスチャ付きの詳細形状で表示され、タワーの最高点が地上 約 131m になること。
- 一人称視点（V）で鉤縄の狙いが効くこと。
- 東寺五重塔が PLATEAU に入っていること（ただし箱型＋相輪の簡易形状）。位置はデータに合わせて補正済み。
- 自動操縦で完走できること。テクスチャ・LOD3 版では 2 回に分けて確認（スタート〜河原町塩小路〜京都駅、河原町塩小路〜ゴール。後半は 2 分 29 秒）。LOD3 で増えた屋上の段差は自動で跳び越える。
- ゴール画面の軌跡（赤線）が、途中で立ち止まっても表示されること。
- タイムアタック：カウントダウン中は動けずタイムも 0 のまま、GO で動き出すこと。区間タイムの表示、ゴール時の自己ベスト判定。
- チーム：同じ合言葉で同じチームに入る／別の合言葉は別チーム／遅い記録ではベストが上書きされない／チーム外・範囲外タイム・短すぎる合言葉は拒否／ゴール画面にチーム内順位とランキングが出る。
- 古い建物だけが壊れること：築1912年・1965年は秒速30mで崩れて通り抜け、同じ1912年でも秒速10mでは壊れず、築1998年・2024年・築年不明は秒速30mでも壊れない。やり直すと元に戻る。
- 地面近くの当たり判定：地上0.5〜4mの水平レイ36本のうち27〜31本が建物に当たる（修正前は0〜4本で、走って建物の下をすり抜けられた）。
- 上記をすべて入れた最新版で、自動操縦がスタートからゴールまで通しで完走（2分49秒、途中で古い建物を9棟崩した）。

## まだ確認できていないこと

- **人がマウスで遊んだときの操作感**。物理と完走は自動操縦で確かめたが、狙いやすさ・速度感・難易度は試遊で調整が必要（`src/main.js` 冒頭の調整値）。
- 実機でのフレームレートとメモリ。建物の写真は標準で 2048px に縮小して持つ（`?hq` の 4096px では近くの建物を読み込む前にキャッシュ上限に達することがあったため標準から外した）。内蔵 GPU のノート PC では要確認。タイル読み込み時に 0.1〜0.4 秒の引っかかりが出ることがある。
- ゲームパッド・スマートフォン操作は未対応。
- 地形・橋・道路・川は平面の絵で、立体ではない。京都市の PLATEAU には地形（DEM）と河川の 3D モデルがなく、橋梁・道路の 3D モデル（LOD3）は祇園周辺のごく一部だけでコース上に無いため。川は「流れが重くて遅くなる」扱い。
- 鉄道の線路は PLATEAU に該当データが無く描いていない。
- 試遊者による評価。
- 別の PC からインターネット越しに接続しての複数人プレイ。

## 構成

- `index.html` … 画面と HUD
- `src/config.js` … 原点、コース、データ URL（実地理に関わる値）
- `src/geo.js` … 緯度経度 → ゲーム内座標
- `src/main.js` … 物理、鉤縄、カメラ、読み込み、ゴール演出
- `src/ground.js` … 地面（PLATEAU の土地利用・道路モデルの描画、水面の判定）
- `src/terrain.js` … 建物の足元から地面の高さを推定
- `src/breakable.js` … 築年数の古い建物の崩壊
- `src/timeattack.js` … 自己ベスト・区間タイム・チーム API の呼び出し
- `worker/index.js`、`wrangler.toml` … Cloudflare Workers 版のサーバー（公開に使っているもの）
- `server.js` … 同じ API の Node.js 版（依存パッケージなし）
- `dist/game.js` … ビルド結果（`npm run build`）
- `Dockerfile` … ホスティングに載せるとき用
- `demo/` … デモ動画
